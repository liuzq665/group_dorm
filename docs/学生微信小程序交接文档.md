## 4. 业务规则与接口边界

- 留宿批次由管理员设置一个连续的开放起止区间；学生可以在该区间内申请多个不重叠日期段。小程序已做日期段之间的重叠检查；日期段是否在开放区间内仍须依赖后端校验，并在小程序中联调错误提示。
- 学生数据范围由后端 `CurrentUser` 和服务层校验控制。小程序的学生角色检查用于页面引导，不代替服务端授权。
- 报修使用 `RepairController` 的 `/repair-orders`、`/repair-history` 及工单操作接口。撤销工单的后端重新提交接口为 `POST /repair-orders/{id}/resubmit`。
- 留宿使用 `StayController` 的 `/stay/current`、`/stay/applications` 及提交、撤回接口。留宿申请附件应使用 `POST /stay/applications/files`。
- 个人资料、住宿和消息接口在 `ManagementController`；登录在 `AuthController`。
- 现有网页端仍是四角色管理与学生操作的可用参考；小程序仅负责学生端。
